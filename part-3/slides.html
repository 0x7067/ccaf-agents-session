The mental model · 1 of 3

Who teaches Claude your kitchen?

Nobody. Every session starts from zero. The model has no memory of your project.
Part 1 hammered it: every API request is independent. The same holds between sessions. Nothing carries over.
Claude Code is a host, and hosts load files into the model's context, the window of text it can see this turn. That is how your rules reach the model.
Retyping the same instructions every session does not scale. Files that load at the right moment solve this.
Restaurant modelA new chef walks in every night. The kitchen does not re-explain itself out loud; it hangs the rules where the chef will read them.

Four loading moments. Each gets a name and a slide of its own.

alwaysThe session starts. Your rules and the team's rules load before your first message
conditionalA file matches. Rules scoped to that folder or file kind join in
on demandYou type /name. Only that skill or command loads
unattendedThe night shift. claude -p loads the same files with nobody in the room, at 3 a.m.
The mental model · 2 of 3

CLAUDE.md is the staff handbook

One markdown file with what you would tell a new colleague: commands, conventions, architecture decisions.
Loaded automatically at session start, before your first message.
It is instruction, not configuration. Claude tries to follow it. Guidance, not a locked door.
The longer it grows, the less of it is reliably honored. Emphasis is a budget: reserve IMPORTANT for the two or three rules that hurt when broken.
Restaurant modelThe handbook hangs by the time clock. Everyone reads it at shift start. Nobody memorizes a forty-page handbook.
# Basil Bistro — kitchen handbook

- Prep standards: @./docs/prep-standards.md
- Test command: npm run taste
- Never invent menu items. The menu is the
  source of truth.
- End every shift with the close checklist.

The handbook · ask vs enforce

The handbook asks. The sprinkler doesn't.

Restaurant modelThe handbook says "keep the fryer below 190 °C."
The sprinkler system does not read the handbook.
It trips at 200 °C whether anyone is watching or not.
on paper

CLAUDE.md: "Never push to main"

Wording the model tries to follow.

Followed most of the time, not guaranteed.
A distracted chef can still push.
in code

PreToolUse hook: block the push

Code that runs at a fixed point in the loop.

Deterministic. The push is stopped even when Claude tries it.
Right tool for critical business rules.
The reliability split: prompts ask (~90%), hooks enforce (100%). Money, legal, safety → hooks. Style and flow → the handbook.
The handbook · @path imports

@path: staple the recipe card into the handbook

@ sits immediately before the path. Relative paths resolve against the file that contains the import.
Imports can nest, at most 5 levels deep.
Organization, not context savings. Imports are expanded inline at launch, so the full text still loads into context.
Restaurant modelThe handbook says "for prep standards, see the card on the fridge." Before the shift starts, someone pulls that card off the fridge and staples it into the handbook. The chef reads one document, not two.

The handbook · path-scoped rules

.claude/rules/: laminated cards pulled only for matching tickets

Each rule file carries a paths: list in YAML frontmatter.
A rule loads only when the session touches a matching file. Everything else stays out of context.
Kind vs place: a paths glob fits conventions that follow a file type anywhere (tests). A station card fits conventions tied to one directory.
// .claude/rules/fryer-safety.md
---
paths: ["kitchen/**/*"]
---
Check oil temperature before the first batch.

// .claude/rules/tasting-rules.md
---

---
Score with the fixed card: appearance,
balance, temperature.

On demand · 2 of 2

What the card permits: SKILL.md frontmatter

---
name: prepare-dough
description: Mix flour, water, and yeast to spec,
  knead, proof until doubled, and report when
  the dough is ready to bake.
context: fork
allowed-tools: ["Read", "Grep", "Glob", "Write"]
argument-hint: "Recipe to follow, e.g. pizza-dough"
---
The chef never sees the mixing details. context: fork hands the job to a junior chef in the back. One result comes back: dough ready, or start over.
allowed-tools is the security boundary. This card permits Read, Grep, Glob, Write. The junior chef cannot run shell commands or delete files.
argument-hint asks for the missing argument: "which recipe?"
Skill vs handbook: on demand vs always loaded.
Restaurant modelThe chef says "/prepare-dough pizza-dough" and walks away. The junior chef reads the recipe, mixes, kneads, proofs. The chef gets back "dough is ready" or "it didn't work out." No flour on the chef's hands.

The night shift

claude -p: order delivery, don't dine in

Restaurant modelDine-in means driving to the restaurant, sitting down, talking to the waiter, waiting for the food.
Delivery is one command: what you want, where to send it, done. That is claude -p.
-p (--print): one order, no conversation. Prints to stdout, exits. Never waits for a person.
Plain prose is a handwritten note. A pipeline needs a printed receipt.
--output-format json + --json-schema: a receipt with fixed fields. File, line, severity, fix. Ready to post as inline comments.
# one delivery order, structured receipt
claude -p "Close-of-day check…" \
  --output-format json \
  --json-schema '{"type":"object",
    "properties":{"findings":{…}},
    "required":["maxPrepBatch","findings"]}'

# the receipt your CI parses
{ "type": "result", "result": { … } }
